## M6 — 배포 후 관측 (지금 여기)

**목표**: `LLM_RENDER_SAMPLE`을 0.25 → 1.0으로 올려도 되는 근거를 실트래픽에서 확보.

지금까지의 모든 수치는 **제가 만든 표본 3건**에서 나왔습니다. 실사용자 입력은 훨씬 지저분하고, 그때 무엇이 깨지는지는 표본으로 알 수 없습니다.

관측 도구: `node scripts/prod-metrics.cjs` (phase-zero 카운터 · 일일 예산 · 토큰 · 폴백률)

### 6-1. App Check를 `enforce`로 (수일 내)

사이트 키가 붙었으므로 클라이언트가 토큰을 발급하기 시작합니다.

- **확인**: Cloud Logging에서 App Check `missing` 판정이 사라졌는지
- **올린 뒤**: `APP_CHECK_MODE=enforce`로 재배포
- ⚠ **로그가 깨끗해지기 전에 올리면 안 됩니다.** 이미 페이지를 열어 둔 사용자는 구버전 번들로 토큰 없이 요청을 보내고, 전부 401을 받습니다
- 완료 조건: `enforce` 상태에서 정상 사용자 완주율이 이전과 같음

### 6-2. 속도 제한 홉 수 검증 (즉시)

`RATE_LIMIT_XFF_DEPTH=1`이 App Hosting(Google LB 뒤)에서 맞는지 **모릅니다.**

- **어긋나면 조용히 망가지지 않고 눈에 띄게 막힙니다** — 모든 요청이 한 키로 묶여 정상 사용자가 429를 받습니다(A0에서 의도한 실패 방향)
- **확인**: 429 발생률. 0에 가까우면 정상, 급등하면 깊이가 틀린 것
- 완료 조건: 실트래픽에서 429가 남용 패턴에서만 발생

### 6-3. 반사실 방향 반전 — 관측 후 판단

**모델이 "가지 않은 길" 대신 실제로 택한 길을 서술해도 현재 검사는 통과시킵니다.** 배포 전 모델 비교에서 실제로 관측됐습니다(WORLDMODEL §5.D-a).

원인이던 "L2가 확정한 심볼을 L5에 안 넘김"은 고쳤으므로 발생 확률은 크게 낮췄지만, **발생하면 못 잡습니다.**

- **신호**: 피드백에 "내 얘기와 반대", "이건 실제로 있었던 일인데" 류
- **검사를 넣으려면** 한국어 산문의 극성을 판정해야 하고 그건 L2의 일이라, 자기 출력에 L2를 다시 돌리는 비용이 듭니다. **관측된 빈도를 보고 결정합니다** — 0에 가까우면 넣지 않습니다
- 완료 조건: 방향 반전 신고 0건 또는 검사 도입

### 6-4. L2 커버리지 (`unknownRate` < 20%)

- `forkUnknowns` 컬렉션(7일 TTL)에 미분류 원문이 쌓입니다
- **주 1회 사람이 읽고 `PATTERNS`에 추가** — 온톨로지 변경은 항상 사람 승인. 이것이 월드모델의 진화 루프입니다
- 패턴이 늘수록 LLM 호출이 줄어 비용도 함께 내려갑니다
- 완료 조건: `unknownRate` 하향 추세 + 20% 미만

### 6-5. 폴백률 (< 5%)

- `renderAttempt` 대비 `renderSucceeded`. 현재 7/7이지만 **표본이 작아 의미 없습니다**
- 5%를 넘으면 원인을 나눠 봐야 합니다: `renderFidelityFail_check`(충실성) / `_schema`(형식) / `renderFallback_error`(API)
- 완료 조건: 표본 100건 이상에서 5% 미만

### 6-6. 지연 12.9초의 실제 영향

- 카드 공개는 즉시(`reveal` 청크 선행)이고 12.9초는 **본문 대기 시간**입니다
- `effort` 조정으로는 안 줄어듭니다(WORLDMODEL §5.C에서 반증). 줄이려면 산문을 짧게 하거나 모델을 바꿔야 하고 둘 다 제품 가치를 건드립니다
- **먼저 이탈률을 봅니다.** 문제가 아니면 손대지 않습니다
- 완료 조건: cards → reading 이탈률이 배포 전과 유의하게 다르지 않음

### 6-7. 노출 상향

위 게이트를 통과하면 `LLM_RENDER_SAMPLE`을 **0.25 → 0.5 → 1.0**으로 단계 상향. 환경변수 한 줄이며 되돌리기도 한 줄입니다.

동시에 `LLM_DAILY_CALL_BUDGET`(현재 500 = 하루 최대 $10)이 실트래픽을 감당하는지 재확인합니다 — **베타 규모에는 오히려 낮은 편**입니다.

### M6 완료 조건

- App Check `enforce` 상태에서 완주율 유지
- 429가 남용에서만 발생
- `unknownRate` < 20%, 폴백률 < 5% (표본 100건 이상)
- `LLM_RENDER_SAMPLE = 1.0`

**목표**: 악용·과금 사고·법적 리스크 없이 공개 트래픽을 받을 수 있는 상태.

### 1-A. 남용 방지 ✅

현재 `/api/reading/session`은 인증·제한 없이 Firestore 쓰기를 유발합니다. 스크립트 한 개로 문서와 비용을 무한 생성할 수 있습니다.

- **Firebase App Check** (reCAPTCHA Enterprise) 도입, API 3개 라우트에서 토큰 검증 후 처리
- **속도 제한** 2단계
  - IP 기준: 세션 생성 시간당 N회 (App Hosting 앞단 또는 Firestore 카운터 문서)
  - 세션 기준: 이미 트랜잭션으로 보호됨(`selectReadingSession`) — 유지
- **입력 크기 상한 재확인**: `story` 600자 제한은 있으나 요청 바디 전체 크기 제한 없음
- 완료 조건: 인증 없는 반복 호출이 429로 차단되고, 정상 사용자는 영향 없음

### 1-B. 법적 문서 ✅ (사업자 정보 잔여)

생년월일시 + 과거 사건 서술은 민감도가 높고, 만 14세 게이트를 두고 있다는 것 자체가 법정대리인 동의 체계를 전제로 합니다.

- `/privacy` 라우트: 수집 항목, 보유 기간(7일 TTL), 파기 방법, 처리 위탁(Google Cloud), 이용자 권리, 만 14세 미만 미제공 명시
- `/terms` 라우트: 오락 목적 고지, 의료·법률·재무 조언 아님, 면책
- 랜딩 모달은 요약 유지 + 전문 링크
- 완료 조건: 두 라우트가 정적 페이지로 존재하고 푸터·모달에서 도달 가능

### 1-C. 안전 분류기 강화 ✅ (2026-08-17)

`src/lib/safety.ts`로 분리하고 **L2의 `normalizeText()`를 공유**합니다. 공백·문장부호 제거 + NFC 정규화라, `"이 혼"`·`"죽.었"`·`"자-살"` 류가 같은 규칙으로 막힙니다. **정규화가 두 벌이면 한쪽만 강해지고 다른 쪽이 뚫립니다.**

**사유 코드**를 붙였습니다 — `self-harm` / `death` / `violence` / `sexual-violence` / `accident` / `loss`. `internalMetrics`에 `safetyBlock_<사유>`로 집계하며 **원문은 저장하지 않습니다.**

**차단 목록 자체는 건드리지 않았습니다.** 무엇을 막을지는 안전 정책이지 코드 정리가 아닙니다. 아래 오탐 조정은 `safetyBlock_*`이 쌓인 뒤 근거를 갖고 판단합니다.

**픽스처가 실제 결함을 잡았습니다** — `"성폭력"`이 `"폭력"`을 포함해 `violence`로 분류됐습니다. 사유 코드가 뒤섞이면 오탐 조정 근거가 무너집니다. 객체 키 순서에 기대지 않도록 배열로 바꾸고 구체적인 군을 앞에 뒀으며, **그 순서 의존을 픽스처로 고정**했습니다.

검증: `scripts/safety-fixtures.ts` — 우회 20건 전부 차단 · 정상 서술 8건 오탐 없음 · 빈 입력 · 사유 코드에 원문 미노출. **운영 실측으로도 확인**(`"이 혼"` → 422, 정상 서술 → 200).

#### 남은 것 — 오탐 조정 (관측 후)

- **미탐**: 띄어쓰기·오타·자모 분리("이 혼", "죽 었") 우회 → 정규화(공백·특수문자 제거, NFC) 후 매칭
- **오탐**: "이혼", "교통사고"가 성찰의 정당한 소재일 때도 무조건 차단 → 차단 대신 "이 주제는 다루지 않습니다" 안내 + 대체 경로 제시로 톤 조정
- 차단 사유별 로깅(내용 미저장, 사유 코드만)으로 임계값 조정 근거 확보
- 완료 조건: 우회 케이스 픽스처 20건 추가, 전부 차단

## M2 — 서사 품질 ✅ (2026-08-16~17)

**B안(LLM 하이브리드)으로 완료했습니다.** 아래는 당시 판단 기록이며, 실제 설계·구현·실측은 [WORLDMODEL.md](./WORLDMODEL.md)에 있습니다.

**결정 당시와 달라진 것 하나** — 이 문서는 "LLM이 문장화를 담당"이라고만 했는데, 실제로는 **두 곳**에 들어갔습니다. 사용자 서술을 *이해*하는 층(L2)이 없으면 "내 이야기로 읽히는 서사"가 애초에 불가능했기 때문입니다. 경계 계약은 WORLDMODEL §0.2에 있습니다.

| 완료 조건 | 결과 |
| --- | --- |
| 스펙 위반 폴백률 < 5% | 배포 시점 0/7 — **표본 부족, M6-5에서 판정** |
| 킬스위치 ON에서 완전 동작 | ✅ 픽스처로 단언 |
| 세션당 비용이 예산 내 | ✅ $0.014 (WORLDMODEL §5.E) |
| 동일 입력 문장 중복률 | ✅ 사용자 서술이 반영되므로 구조적으로 해소 |

**문제**(당시 기록): 서사가 십신 5축 템플릿입니다. 한 사람이 두 번 이용하거나, 두 사람이 결과를 비교하면 같은 문장이 나옵니다. 재방문·공유가 성립하지 않는 근본 원인이 여기입니다.

### 선택지

| | A. 템플릿 확장 | B. LLM 하이브리드 (권장) |
| --- | --- | --- |
| 방식 | 축별 문안 변형을 3~5배로 늘리고 사건 카테고리별 분기 추가 | 엔진이 `NarrativeSpec`(사실·전환점·불변 주제)을 결정적으로 만들고, 문장화만 모델이 담당 |
| 비용 | 0 | 세션당 1회 생성분 |
| 지연 | 0 | 수 초(스트리밍으로 은폐 가능) |
| 재현성 | 완전 | 스펙 고정 + 시드로 부분 확보 |
| 품질 상한 | 낮음(작성량에 비례) | 높음 |
| 리스크 | 없음 | 비용 폭주, 스펙 이탈, 안전 문구 붕괴 |

**B를 권장합니다.** 이유: 서비스의 가치가 "정확한 예측"이 아니라 "내 이야기로 읽히는 서사"에 있고, 그 부분만 정확히 모델이 잘합니다. 계산·전환점·안전 판단은 그대로 결정적 엔진이 담당하므로 리스크가 문장 레이어에 격리됩니다.

### B안 설계

1. **봉인은 이미 지연 생성과 호환됩니다.** `commitment`는 카드의 짧은 선택지 문구(`choice.text`)에만 걸려 있고 서사 본문은 포함하지 않습니다(`reading-engine.ts:576`). 따라서 세션 생성 시 3장 전부의 본문을 만들 필요가 없습니다.
2. **리팩터**: `createReadingSession`은 3축의 `NarrativeSpec`까지만 생성(결정적·무료). `resultFor`(문장화)는 `stream/route.ts`에서 선택된 1장에 대해서만 호출 → **생성 비용 1/3**.
3. **검증 게이트**: 생성 결과를 기존 `validateNarrative`에 그대로 통과시킵니다. 전환점 개월 수 누락, 단정 표현("반드시 일어", "틀림없이"), 우월 결말은 이미 위반으로 잡힙니다. **위반 시 즉시 현행 템플릿 결과로 폴백** — 사용자는 실패를 보지 않습니다.
4. **비용 통제**
   - 환경변수 킬스위치: 켜지면 전 요청이 템플릿 경로로 (README에 예고된 "모델 예산 킬스위치")
   - 일일 예산 상한 도달 시 자동 폴백
   - 동일 입력 해시 캐시
   - 모델·단가는 착수 시점에 재확인 (Claude 최신 모델 기준으로 산정)
5. **스트리밍 교체**: 현재 `setTimeout(240~420ms)` 인위적 지연(`stream/route.ts:73`)을 실제 토큰 스트리밍으로 대체. NDJSON 청크 계약은 그대로 유지 → 클라이언트 무변경.

### 완료 조건

- 동일 입력 10회 생성 시 문장 중복률 측정 가능하고 목표치 이하
- 스펙 위반 폴백률 < 5%
- 킬스위치 ON 상태에서 서비스가 완전히 동작(모델 장애 시 무중단)
- 세션당 비용이 예산 내

랜딩 카피가 "만약사주의 **첫 번째 이야기**"라고 선언하고 있습니다. 이 약속을 지키는 단계입니다.

| **L3 이중 궤적** | 현재 3장 모두 "가지 않은 길"이고 **실제 궤적 개념이 없습니다.** 서사의 차이가 초기 bias에서만 나오도록 같은 `step` 함수로 굴려야 합니다 |
| 남은 유파 결정 | §7-2 신강 임계 · §7-3 용신 취법 · §7-5 형 범위. 해당 층 작업 시 확정 |
| 해외 출생 | `CITY_LONGITUDE`가 국내 11개뿐, 미상은 127.5° 폴백. 입력 폼도 자유 텍스트라 경도를 얻을 수 없습니다(§7-7) |

### 제품

- **M3 두 번째 이야기** — 같은 원국 재사용. L2 도입으로 **"같은 사람 + 다른 갈림길 = 다른 결과"가 이제 성립합니다.** 배포 전에는 불가능했던 것입니다
- **결과 공유 카드** — 사건 서술 절대 미포함, 명시적 옵트인
- **결과 재열람** — 현재 localStorage 7일뿐이라 기기가 바뀌면 소실
