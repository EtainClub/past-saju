# 내 사주 확장안 — 결정론 차트에 LLM을 어디에, 왜 붙일 것인가

작성일: 2026-08-18 · 관련: [ROADMAP.md](./ROADMAP.md)(M3 재방문·확산, M4 수익화) · [WORLDMODEL.md](./WORLDMODEL.md)(L1~L5 경계 계약)

이 문서는 "내 사주가 LLM 없이 결과만 보여준다"는 관찰에서 출발해, 그 화면(과 그 옆의 「이야기」 화면)을 더 활용할 방법을 검토한 기록입니다. 결론부터: **내 사주 화면에 LLM을 넣는 것 자체가 목표가 아닙니다.** WORLDMODEL.md가 이미 확립한 경계(L1 계산은 결정론, LLM은 이해·표현 경계에만)를 그대로 유지하면서, 지금 완전히 분리돼 있는 "내 사주"와 "이야기" 두 화면을 사용자 관점에서 하나의 경험으로 좁히는 것이 실제 기회입니다.

---

## 0. 요약

| 제안 | LLM | 비용 | 리스크 | 우선순위 |
| --- | :---: | --- | --- | --- |
| **A. 축 브릿지** — 내 사주 축 분포와 이야기 카드가 왜 연결되는지 코드로 설명 | ❌ | 0 | 낮음 | 1순위 |
| **B. 오늘/이 대운의 흐름 카드** — 짧은 시의성 있는 해설 | ✅ (L5 재사용) | 세션당 소액, 캐시 필요 | 낮음~중간 | 2순위 |

| **D. 종합 리포트** (유료 후보) | ✅ (A+B+C 조합) | — | M4 법률 검토 선행 | 4순위 |

## 1. 현재 상태 — 두 화면은 왜 이렇게 다른가

| | 내 사주 (`ChartScreen`, `if-saju-experience.tsx:314`) | 이야기 (만약사주 서사) |
| --- | --- | --- |
| 데이터 | `ChartSummary` — 사주팔자·오행·신강신약·대운. `summarizeChart()`(`chart/summary.ts`) | `ForkFrame`(L2) → `NarrativeSpec` → LLM 렌더(L5) |
| LLM | **없음. 의도적 설계** | Haiku 4.5(L2 분류) + Sonnet 5(L5 렌더) — WORLDMODEL A0~A4 완료·배포됨(25% 샘플) |
| 목적 | "계산된 것만 낸다. 길흉·예언을 말하지 않는다"(`chart/summary.ts:8-15`) | 사용자가 서술한 갈림길에 대한 반사실 서사 |
| 축 체계 | `axes: Array<{ axis: TenGodAxis; count }>` — 식상/관성/재성/인성/비겁 | 같은 `TenGodAxis` 5축을 `rankedAxes()`가 카드 3장으로 압축 |
| 재방문 유인 | 없음 — 생년월일이 안 바뀌면 화면이 고정 | 두 번째 이야기(M3, 게이트 대기) |
| 세션당 비용 | $0 | $0.014 (실측, WORLDMODEL §5.E) |

**내 사주가 LLM이 없는 것은 버그가 아니라 명시적 설계입니다.** `chart/summary.ts` 헤더 주석과 `ChartScreen` 함수 주석이 "해석하지 않는다"를 두 번 못박고 있고, 골든 43건이 이 화면의 수치 정확성을 보장합니다. 여기에 LLM을 얹어 "해석"을 시작하면 이 화면이 보장하던 것(사실과 해석의 분리)이 무너집니다. **따라서 이 문서의 모든 제안은 ChartScreen 자체를 해석 화면으로 바꾸지 않는 것을 전제로 합니다.**

---

## 2. 문제 진단

사용자가 지적한 "결과만 보여준다"는 관찰을 구체화하면 세 가지입니다.

1. **질문에 답할 창구가 없다.** 사용자가 자기 명식(신강·신약, 오행 분포, 대운)을 보고 나면 자연히 "이게 무슨 뜻이지?"라는 질문이 생기지만, 이 화면 안에는 답을 얻을 방법이 없습니다. 해석은 「이야기」 탭에서만, 그것도 사용자가 입력한 **특정 갈림길에 한정**해서만 나옵니다.
2. **두 화면이 같은 축을 쓰면서도 서로 모른 척한다.** 내 사주의 `axes` 분포와 이야기 탭 `rankedAxes()`(`reading-engine.ts:150`)는 같은 `TenGodAxis` 5축(`ten-god-axis.ts`)을 공유합니다. 그런데도 사용자는 "왜 하필 이 세 갈래 카드가 나에게 나왔는지"를 내 사주 화면에서 확인할 방법이 없습니다. 두 화면이 사실은 하나의 명식에서 나온 것인데 별개 제품처럼 보입니다.
3. **재방문 유인이 없다.** 이야기 탭은 새 갈림길을 입력해야 다시 볼 거리가 생기고(입력 진입장벽), 내 사주는 생년월일이 바뀌지 않는 한 정적입니다. ROADMAP M3(재방문·확산)가 "두 번째 이야기"만 언급하는데, 내 사주 쪽에도 낮은 비용의 재방문 유인이 있을 수 있습니다.

---

## 3. 제안 — 4가지 방향

경계 원칙은 WORLDMODEL §0.2를 그대로 따릅니다: **L1(명식 계산)은 절대 결정론, LLM은 이해(L2)·표현(L5) 경계에만.** 아래 A~D는 이 경계를 넓히지 않고, 그 경계 위에 새 표면을 추가하는 순서입니다.

### A. 축 브릿지 — LLM 없이, 코드로 두 화면을 연결

내 사주의 `axes` 테이블 옆에 "이 축이 왜 이야기 탭 카드에 등장(하거나 안)했는지"를 결정론적으로 표시합니다. `rankedAxes()`는 이미 `usefulAxes`/`hostileAxes`와 원국·월지·대운 가중치를 계산하고 있으므로, 이 근거를 문장 템플릿(`AXIS_COPY` 패턴과 동일한 방식)으로 노출하면 됩니다.

- **비용 0, LLM 리스크 0.** 순수 리팩터/UI 작업.
- **효과**: "내 사주"와 "이야기"가 하나의 명식에서 나왔다는 감각을 줍니다. 지금은 완전히 분리된 두 화면처럼 보이는 것이 가장 저렴하게 고칠 수 있는 문제입니다.
- 구현 위치: `ChartScreen`의 축 분포 섹션(`if-saju-experience.tsx:372-383`) 옆에 `usefulAxes`/`hostileAxes` 근거 문장 추가. `summarizeChart()`가 이미 갖고 있지 않은 계산이므로 `rankedAxes()`의 근거 산출 로직 일부를 `chart/summary.ts`가 재사용하도록 소폭 리팩터 필요.

### B. 오늘/이 대운의 짧은 흐름 카드 — L5 인프라 재사용

내 사주에 이미 계산돼 있는 현재 대운(`chart.luck.pillars[currentIndex]`)과 오늘 날짜를 조합해, "지금 대운이 어떤 의미인지"를 1~2문장으로 렌더링합니다. `render/llm.ts`·`render/fidelity.ts`·`llm/budget.ts`를 그대로 재사용 — 입력은 순수 Fact(대운 간지, 십신축, 신강/신약)만 넘기고, 예언·의료·법률 조언 금지 검사(`checkFidelity`)를 그대로 적용합니다.

- **재방문 유인 후보.** 매일 와도 명식 자체는 안 바뀌는 문제를, "오늘 시점에서 바라본 해설"로 우회합니다. M3(재방문·확산) 목표와 직결됩니다.
- **캐시 필수.** 대운은 10년 단위로만 바뀌므로 하루 1회(또는 대운 변경 시에만) 생성하고 캐시해야 합니다. 캐시 없이 열 때마다 생성하면 재방문할수록 비용이 느는 역설이 생깁니다.
- 리스크는 낮습니다 — 이야기 탭 L5와 동일한 grounding·fidelity 계약을 그대로 물려받기 때문입니다.

### C. 명식 Q&A — 사용자가 자기 명식에 대해 자유 질문

사용자가 "왜 신약이라는 거예요?", "대운이 뭔가요?", "이 시기에 뭘 조심해야 하나요?" 같은 질문을 자유 텍스트로 던지는 기능입니다. **이것이 사용자가 요청한 "질문에 답한다"에 가장 직접 해당하는 제안이자, 이 문서에서 가장 위험한 제안입니다.**

**설계 원칙**: LLM은 `ChartSummary` 필드만 Fact로 받고, 답변은 그 Fact를 벗어나지 못해야 합니다 — L5가 `factIds`로 문단을 스펙에 묶는 것과 같은 패턴입니다.

**안전장치 3중** (착수 전 반드시 설계):

1. **스코프 제한.** 질문이 사주/명식 범위를 벗어나면(의료·법률·재무·타인 신상, 사주와 무관한 잡담) 거절합니다. `safety.ts`의 정규화·차단 사유 코드 패턴을 재사용하되, 지금은 정해진 슬롯(`story`/`outcome`/`alternative`)만 검사하는 것과 달리 **완전 자유 텍스트**가 새 공격면입니다.
2. **사실 이탈 검사.** 답변이 `ChartSummary`에 없는 사실(구체적 직업 예측, 특정 사건의 발생 시점, 병명 단정 등)을 말하면 거부합니다. `checkFidelity`를 확장해 "인용된 사실이 전달한 Fact 집합의 부분집합인가"를 검사해야 합니다.
3. **비용 상한.** 대화형이므로 세션당 1회가 아니라 **턴당** 비용이 발생합니다. `llm/budget.ts`의 일일 예산을 L2/L5와 공유할지 별도 상한을 둘지 결정이 필요하고, 세션당 턴 수 상한(예: 3턴)을 권장합니다.

Q&A는 이야기 탭보다 안전장치가 두꺼워야 합니다 — 이야기 탭의 자유 입력은 세 개의 정해진 슬롯 안에 갇혀 있지만, Q&A는 대화 전체가 자유 텍스트이기 때문입니다.

### D. 종합 리포트 (장기, M4 연계)

내 사주(명식 전체 해설) + 이야기(만약사주 결과)를 하나로 묶은 심화 리포트. ROADMAP M4가 "심화 리포트를 별도 상품으로"를 이미 검토 항목으로 남겨두고 있습니다 — A/B/C가 이 리포트의 소재가 됩니다. 유료화이므로 ROADMAP이 명시한 대로 **법률 검토(전자상거래법 고지·환불·청약철회)가 선행**되어야 하고, 지금은 사장님 지시로 생략된 상태입니다.

## 4. 하지 않을 것 / 조심할 것

- **ChartScreen 자체를 해석 화면으로 바꾸지 않습니다.** `chart/summary.ts`의 설계 원칙("길흉·예언을 말하지 않는다")은 유지합니다. LLM이 붙는 자리는 화면 하단의 별도 섹션(카드/Q&A)으로 명확히 분리해, 골든 43건이 보장하는 "사실 계산"과 "해석"의 경계를 시각적으로도 지켜야 합니다.
- **Q&A는 새로운 안전 표면입니다.** 지금 `safety.ts`가 막는 것은 정해진 슬롯의 텍스트고, 자유 질문은 훨씬 넓은 공격면(탈옥 시도, 무관한 질문 남용, 반복 재질문으로 예산 소진)을 엽니다. C안은 스코프 제한 시스템 프롬프트 + 거절 픽스처 세트가 먼저 있어야 착수할 수 있습니다.
- **비용 통제 구조가 지금과 다릅니다.** B·C는 세션당 1회였던 기존 L2/L5 모델과 달리 "여러 번 호출될 수 있는" 기능입니다. `LLM_DAILY_CALL_BUDGET`을 그대로 공유하면 이야기 탭의 예산을 깎아 먹으므로, 레이어별 상한 분리를 검토해야 합니다.

## 5. 도입 순서 제안

1. **A (축 브릿지)** — 비용 0, 즉시 착수 가능. 두 화면의 단절감부터 해소합니다.
2. **B (오늘의 대운 카드)** — 기존 L5 인프라 재사용, 캐시 설계 후 착수. M3 재방문 지표에 바로 연결됩니다.
3. **C (명식 Q&A)** — 안전판(스코프 제한, 거절 픽스처, 턴 상한, 비용 상한)을 먼저 설계한 뒤 착수.
4. **D (종합 리포트)** — M4 게이트(M3 지표) 통과 후, 법률 검토 완료 후.

M6(배포 후 관측)가 아직 끝나지 않은 상태이므로, A를 제외한 B·C·D는 M6 완료 조건(App Check `enforce`, 폴백률 <5%, `unknownRate` <20%) 이후에 순서대로 검토하는 것이 ROADMAP의 진행 원칙("새 기능보다 지금 나간 것의 안전 확인 우선")과 맞습니다.

## 6. 열린 질문 (사람이 결정할 것)

- Q&A를 무료로 유지할 것인가, 처음부터 D(유료 리포트)의 일부로만 노출할 것인가.
- B안의 캐시 주기 — 하루 1회 vs 대운이 바뀔 때만. 캐시 정책에 따라 재방문 유인의 신선도가 달라집니다.
- Q&A 대화 로그 보관 정책 — 세션과 같은 7일 TTL로 둘 것인가. 이야기 탭의 `story`/`outcome`/`alternative`와 달리 Q&A는 개인 신상에 관한 질문이 더 자유롭게 들어올 수 있어 `/privacy` 개인정보처리방침 갱신이 필요할 수 있습니다.
- C안의 사실 이탈 검사를 규칙 기반으로 100% 잡을 수 있는지, 아니면 별도 LLM 판정 호출(WORLDMODEL §3.3이 "3단계로 미룬" 것)이 결국 필요한지.
