## 만드는 법

**로고** — `scripts/toss-assets.tsx`가 생성합니다.

```bash
npx tsc scripts/toss-assets.tsx --outDir .test-dist --module commonjs \
  --moduleResolution node --target ES2020 --lib ES2022,DOM \
  --esModuleInterop --skipLibCheck --jsx react-jsx
node .test-dist/toss-assets.js
```

파비콘(`src/app/icon.svg`)·OG 이미지와 **같은 마크**를 씁니다 — 원, 세 획,
중심점. 세 획은 갈림길이고 중심점은 고른 하나입니다. 마크가 다르면 앱
목록에서 같은 서비스로 안 보입니다.

**스크린샷** — 실제 화면 위에 헤드라인·배지를 얹은 **마케팅 합성샷**입니다. 밋밋한 전체화면보다
특징이 한눈에 들어와야 앱인토스 목록에서 멈추게 합니다.

1. 로컬 개발 서버(`pnpm dev`)를 최신 UI 기준으로 띄우고, 예시 출생정보를 입력해
   각 화면(이야기 결과·카드 선택·오늘의 운세·내 사주·백업 코드)을 390×844 뷰포트에서 실제로 캡처합니다.
   그린 그림이 아니라 **실제 앱 화면**이어야 합니다 — 그리면 실물과 달라지고,
   심사와 사용자 기대가 어긋납니다.
2. 최종 크기 636×1048을 그대로 쓰는 HTML/CSS 템플릿을 만듭니다 — 둥근
   검정 테두리, 브랜드 마크(또는 탭 글리프) 배지, 굵은 헤드라인 2줄, 서브텍스트, 그 아래
   폰 프레임에 1번의 스크린샷을 위쪽부터 가득 채워 `overflow:hidden`으로 하단을
   자릅니다(실제 화면이 길어서 자연스럽게 끝이 잘립니다).
3. 그 HTML을 `file://`로 열고 `take_screenshot(fullPage: true)`로 캡처합니다.
   이 환경은 창 높이가 실제 화면보다 작아 `resize_page`만으로는 1048px 뷰포트를 못
   얻지만, `fullPage`는 문서의 실제 높이(HTML에 박아 둔 1048px)를 그대로 받아서 정확히
   636×1048이 나옵니다 — 자르거나 배경색을 채울 필요가 없습니다.

## 다시 찍어야 할 때

화면을 바꾸면 스크린샷도 낡습니다. 특히 하단 탭·「내 사주」·입력 예시는
최근에 추가된 것이라, 이후 UI를 손대면 여기도 함께 갱신해야 합니다.
